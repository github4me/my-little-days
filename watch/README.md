# Apple Watch companion

Native implementation for milk feeds (not pumping), nappies and sleep. The
`watchOS 9.4+` SwiftUI app is embedded in the existing iPhone app by
`plugins/with-watch-companion.js`. Its bundle identifier is the iPhone bundle ID
plus `.watchkitapp`. The config plugin declares the additional EAS credential
target before prebuild, copies versioned sources, generates an opaque RGB Watch
icon from the existing artwork, and
recreates the target/embedding without duplicate build phases.

## Boundaries

- `Shared/WatchProtocol.swift`: Foundation-only, versioned transport and local
  projection. No access/refresh tokens, photos or full family history.
- `WatchApp/WatchStore.swift`: atomic, backup-excluded, first-unlock-protected
  Watch outbox. Commands keep UUIDs across retry/reboot. Current actions do not
  wait for a network response.
- `modules/watch-bridge/ios/`: independent native iPhone receiver, durable inbox
  and bounded receipt cache. JavaScript applies commands through existing domain
  services; a WatchConnectivity receipt never means that SQL accepted a record.
- The phone assigns monotonically increasing generations and snapshot sequences.
  Workspace changes/invalidation advance the generation, temporary unavailability
  does not. Expired context pauses recording; it does not reroute pending records.
  Family context expires at most 24 hours after authoritative phone validation.
- Records from previous generations remain quarantined on Watch, not shown or
  uploaded in the next family. In this first implementation recovery of those
  records requires the original context and is not an automatic merge/export.
- Existing iPhone push alerts are forwarded by Apple. Watch does not register a
  separate APNs token or perform direct server requests.

## Local checks

From the repository root:

```sh
node --test plugins/tests/watch-companion.test.cjs
node plugins/tests/prebuild-watch.cjs
```

This tests credentials declaration, real installed Expo template target generation,
embedding, version alignment, opaque RGB icon output and idempotence. It is **not** a native compilation.
The separate prebuild check requires macOS/Linux: Expo explicitly refuses iOS
prebuild on Windows, where that check reports `SKIP`, not success.

On a Mac with Swift 5.9 or newer:

```sh
swift test --package-path watch
npx expo prebuild --platform ios --no-install
cd ios && pod install
xcodebuild -list -workspace MyLittleDays.xcworkspace
```

Use the workspace name printed/generated by Expo if it differs. Build the iPhone
scheme for a paired physical iPhone/Watch in Xcode. Confirm both target signing
identities and provisioning profiles, companion installation, background durable
receipt and replay before a production-connected acceptance build. TestFlight
requires a new combined native store build, not an OTA update.

The SwiftUI screens use system navigation, lists, buttons, pickers/Crown input,
semantic colours and Dynamic Type. The app-selected `en`, `zh-Hans`, `zh-Hant`,
`fr`, `de`, `hi`, `it`, `ja`, `ko`, `es`, `th` or `vi` locale is sent by the
phone; version 1 contexts from older phones still fall back through the legacy
`en|zh` field. Real Watch VoiceOver, font scaling, battery, keyboard-free input
and WCSession delivery must be checked in every locale on small/large physical
Watch devices.

The Windows implementation environment has no local Swift/Xcode toolchain. EAS
build `24af9879-54a8-4044-998a-5ce4197536b2` subsequently compiled and signed the
combined app (0.2.1 build 31); IPA inspection confirmed the embedded Watch target.
Apple subsequently rejected its alpha-channel icon. The packaging fix is included
in replacement build 32; see the manual runbook for Apple acceptance status.
**Physical Watch installation, connectivity and notification delivery remain
unverified.** See the
